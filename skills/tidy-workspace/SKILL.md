# 整理工作区（tidy-workspace）

把**当前会话所在工作区**根目录的散落文件，按「同一个项目」分组收进 `NN-中文项目名/`
文件夹。这是周日夜里的自动整理的手动版：同一套规则、同一套账本、同样是只移动不删除。

## 默认就直接整理

用户敲 `/tidy-workspace`、或说「整理一下这个工作区」，就是明确授权了。**一次工具调用做完，别先问、别分两步：**

```
tidy_workspace({ "dryRun": false })
```

真搬这一步本身会走审批卡片，那已经是用户的确认点，不需要你再口头问一遍。

只有这两种情况才用预览（`{ "dryRun": true }`，只读、不碰磁盘）：

- 用户明确说「先看看 / 先预览 / 别动 / 会怎么整理」；
- 上一次整理刚出过错，你想先确认为什么某个文件被跳过了。

## 只有一种情况要先问一句

**预览或结果里 `moves` 是 0，而 `skipped` 里有大量「最近 N 天内改过」。**
这说明配置把新文件挡在了外面（默认最近 1 天不动，免得搬走正在用的截图/脚本）。
这时候问一句「要不要连今天改过的也一起整理」，用户说好，就带 `{ "minAgeDays": 0 }` 再跑一次：

```
tidy_workspace({ "dryRun": false, "minAgeDays": 0 })
```

## 做完要交代三件事

1. 建了几个项目文件夹；
2. 每个夹收了哪些文件（工具返回的 `text` 里已经有现成的一段，直接用）；
3. **撤回命令**——`undo` 字段里那条，原样贴给用户。

用户看不出效果时，还可以让他看 `audit/runs/<runId>.md`（工具返回了 `runId`）。

## 规则（工具自己执行，你不用动手，也不要重复判断）

- 只动工作区根目录**第一层**的文件。子目录一律不进去、不改名、不移动。
- 以数字开头的文件夹（`01-团委档案`、`02-校园听力`）算已经整理好的项目，整棵跳过。
- 文件名保持原样搬进去，不改名——脚本里常写死文件名，改名会打断引用。
- 一组不到 `minFilesPerProject` 个文件就先不建夹，留在原处，结果里写原因。
- 编号接根目录已有编号往后排；撞上已有文件夹名自动加 `-2`。
- 不碰 README、`package.json`、`cordis.patch.yml`、锁文件、隐藏项、
  `.git` / `node_modules` / `build` 这类开发目录。
- 不碰保护名单（成品插件目录、profile 里引用的路径、`protectPaths` / `protectNames`）。
- 只移动不删除。每次运行写 `audit/journal.jsonl` 和 `audit/runs/<runId>.md`，可整批撤回。

## 别做的事

- **不要用 `ops_bash` 自己 `mv` / `move` 文件来「顺手整理」。** 那样没有账本，
  撤不回来，也绕过了保护名单和「最近 N 天」的阈值。整理只走 `tidy_workspace`。
- 不要为了凑够一组，把不相干的文件塞进同一个项目——工具会把太小的组拆回未分组。
- 不要改计划里的编号或项目名去覆盖已有文件夹；避让是工具的事。
- 不要把范围扩大到别的工作区：这个技能只整理**当前会话所在**的那一个。
